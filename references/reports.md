# 报告与汇报材料

根据任务选择一种结构，不机械套用全部栏目。所有成果、比例、金额和进度必须来自用户事实或明确标记待补充。

## 出差报告

推荐结构：

1. 标题：`关于赴[地点]开展[事项]的出差报告`
2. 基本信息：时间、地点、人员、任务目标。
3. 行程与工作开展：按时间或任务模块陈述关键活动。
4. 主要成果：达成事项、获取信息、形成材料、客户或合作方反馈。
5. 问题与风险：事实、影响、原因；不要只写感受。
6. 建议与后续：行动、负责人、期限和所需支持。
7. 费用或附件：仅在用户需要时列明。

摘要示例骨架：`本次出差围绕[目标]开展，共完成[事项]，形成[成果]。目前需重点推进[后续动作]，并关注[风险]。`

## 周报/月报

推荐结构：

```text
[部门/姓名][周期]工作周报/月报

一、本期核心结论
[用 2—4 句概括进展、结果和偏差。]

二、重点工作完成情况
1. [事项]：目标；本期动作；结果/数据；状态。

三、问题与风险
[问题]：影响；原因；已采取措施；所需支持。

四、下期计划
[行动]：预期产出；负责人；完成时间。
```

规则：以结果代替流水账；进度用统一口径；未完成事项说明原因和纠偏动作。若用户只提供零散事项，先按项目或目标归类。

## 工作汇报

根据对象调整重点：

- 向上汇报：先结论和决策请求，再给依据、风险和方案。
- 跨部门汇报：先共同目标、接口和依赖，再给分工、时间点和协作请求。
- 项目复盘：目标、结果、差距、原因、经验、行动，区分事实与判断。
- 阶段总结：总体进展、关键成果、主要问题、下一阶段重点、资源需求。

推荐表达顺序：`结论 → 关键数据/事实 → 原因判断 → 方案或下一步 → 需对方决策/支持`。

## 汇报材料

若用户未指定载体，先生成可直接用于文档或演讲的文字版：

1. 结论式标题：表达核心判断，不只写主题词。
2. 一页摘要：背景、核心成果、关键问题、下一步、需决策事项。
3. 主体模块：每节只回答一个问题，并用证据支持结论。
4. 结尾：明确行动清单、责任人、里程碑与支持请求。

若用于 PPT，保持“一页一结论”，给出页标题和 3—5 条要点；除非用户要求制作演示文稿，否则不要自行生成 PPTX。

## 数据和状态口径

- 已完成：已有可核验交付物或结果。
- 进行中：写明当前阶段、下一节点和预计完成时间。
- 待启动：写明启动条件或依赖。
- 有风险：写明触发条件、影响、缓解措施与责任人。
- 不确定的数据使用 `[待补充：数据及统计口径]`，不得用看似精确的数字代替。
